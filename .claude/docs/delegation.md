# 委譲

## 役割

| 担当 | 受け持つもの |
| --- | --- |
| メイン | 要件の解釈、成功条件の確定、設計判断、委譲、結果の統合、最終判断、ユーザー対応 |
| `researcher` | 実装前の調査、影響範囲の確認、仕様確認、根拠集め。**ファイルを変更させない** |
| `implementer` | 成功条件と対象ファイルが確定した後の実装 |
| `reviewer` | 非自明な実装の後の検査。**対象を編集させない** |

小さな単発作業は委譲しない。サブエージェントは別のサブエージェントを起動しない。

## 使い分け

| 状況 | 判断 |
| --- | --- |
| 調査対象が互いに独立 | 読み取り専用のタスクだけ並列化する。書き込みを含むものは並列化しない |
| 調査 → 実装 → 検査 | **直列**。同時に動かす書き込み担当は 1 体だけ |
| 同じファイルを複数で編集 | **禁止** |
| 認証・権限・課金・個人情報・データ移行・破壊的操作・本番基盤 | **メインが直接判断する** |

## 委譲するときに必ず渡すもの

- 対象ファイル、禁止事項、検証コマンド
- **検算できる形で返させる**（確認したファイル名と件数を書かせる）

実装中に設計変更が必要になったら、独自判断で範囲を広げずメインへ戻す。

## 返ってきたものの扱い

**報告は結論、根拠、未確定事項、検証結果だけに絞らせる。**

**そのまま信じない。** 検算できる数字が含まれていたら、こちらで 1 つ確かめる。
誤った報告を受けた実例がある一方、**こちらの古い前提が誤っていた実例もある**。

## 起動に失敗したとき

同じ委譲を繰り返さない。失敗理由、完了済み、未完了をメインへ戻す。
モデルが使えない場合は Haiku → Sonnet → 親モデル継承の順に落とす。
