# 売買を講義の技法と照らして振り返る

## CRITICAL: 先に読むこと

- **「技法に従えば勝てた」と書かない。** この基盤自身の検証結果は**単独の技法にエッジ無し**で、
  複数が揃った局面も有意ではなかった。見ているのは**教わったとおりに動けていたか**であって、
  その教えが儲かるかではない。
- **金額・株数・口座の識別子を報告書に出さない。** 正本の規約（秘匿）と
  「個人情報は git 管理しない」に反する。騰落率で書く。**道具が既にそう作られている**ので、
  手で付け足さない。
- **「技法が出ていた」は「それを見て買った」ではない。** 同じ日に同じ銘柄が選ばれていた、
  という事実だけ。報告書にもそう書いてある。
- **台帳の期間外は「技法が出ていなかった」ではない。** 確かめられないだけ。
  この 2 つを混ぜると、振り返り全体が嘘になる。

## 用語

| 正式名 | 意味 |
| --- | --- |
| 約定 | 証券会社が記録した 1 回の売買成立。**損益も手数料も入っていない** |
| 持ち高の組み立て | 買いと売りを突き合わせ、建値を平均で追うこと |
| 前向き台帳 | `mcp-tradingview/data/paper-ledger.jsonl`。**結果を知る前に**記録された技法の発火 |
| 照合できた取引 | 建ても決済も台帳の期間に入っている取引 |
| 技法が出ていた | 買った日（と直前 3 日）に、その銘柄を技法が選んでいた |

## ユースケース

### 1. 定例の振り返り

- **Trigger**: 「今年の売買を振り返って」「技法を守れているか見て」
- **Steps**: 約定を取る → 持ち高を組み立てる → 台帳と突き合わせる → 報告書を書く
- **Result**: `derived/trade-reviews/<日付>.md` と、要点を 3 行で伝えた返答

### 2. 期間を指定した振り返り

- **Trigger**: 「7 月以降だけ見て」
- **Steps**: 開始日を第 1 引数で渡す（`review.sh 2026-07-01`）
- **Result**: 同じ形の報告書。**建値のため、取得は開始日の 1 年前から**行う

### 3. 改善点だけ知りたい

- **Trigger**: 「次はどう売買すべきだった？」
- **Steps**: 通常どおり実行し、報告書の「守れていたか」の節を読む
- **Result**: 各項目に**「次に同じ場面が来たら」**が付いている

## 前提条件

| 要る物 | 確認方法 |
| --- | --- |
| mcp-invest-knowledge | `ls ~/dev/me/mcp-invest-knowledge/cmd/trade-review` |
| mcp-tradingview の台帳 | `ls ~/dev/me/mcp-tradingview/data/paper-ledger.jsonl` |
| trade-moomoo と OpenD | `pgrep -f OpenD`。**動いていないと約定を取れない** |
| 現物の口座 ID | `MOOMOO_ACC_ID` に入れる |
| Docker | 約定の取得はコンテナの中で動く |

## 手順

### ステップ 1: 台帳があり、期間が十分か見る

```bash
ls -l ~/dev/me/mcp-tradingview/data/paper-ledger.jsonl
```

**台帳が無いか極端に短ければ、振り返りは成立しない。** 技法が出ていたかを確かめる術が無くなり、
報告書は「照合できた取引 0 件」になる。その場合は**そう報告して止める**。条件を緩めない。

### ステップ 2: 実行する

```bash
MOOMOO_ACC_ID=<現物の口座 ID> sh ~/.claude/skills/review-trades-against-techniques/scripts/review.sh
```

開始日を変えるときは第 1 引数で渡す。

```bash
MOOMOO_ACC_ID=<id> sh .../review.sh 2026-07-01
```

**本番口座を読むので、環境変数の指定が安全装置に引っかかることがある。**
その場合は**回り道をせず**、ユーザーに実行を依頼する（`! <command>` で貼り付けられる）。

### ステップ 3: 報告書を読み、要点だけ伝える

**報告書を丸ごとチャットに貼らない。** 保存先のパスと、次の 3 つだけを伝える。

1. 照合できた件数（と、できなかった件数）
2. 技法が出ていない銘柄を買った割合
3. 保有期間が技法の想定とどれだけ違うか

## 出力

報告書は道具が書く。**チャットに書くのは次の 4 点。**

1. **報告書のパス**
2. **照合できた取引の件数**と、台帳の期間外で確かめられなかった件数（混ぜない）
3. **守れていなかった点**を多い順に 2 つまで
4. **「条件に合った」ではなく「教わったとおりだったか」を見ている**という但し書き

### 入出力の例

**入力**: 「今年の売買を振り返って」

**出力**:

```text
derived/trade-reviews/2026-10-02.md に書きました。

決済 204 件のうち台帳と照合できたのは 44 件（残りは台帳の期間外で、確かめられません）。
・照合できた 44 件の 61% が、どの技法も出ていない銘柄
・技法が出ていた 17 件は 17 件とも、技法の想定より早く手仕舞い（保有の中央値 2 日 / 技法は 20 日前提）
```

## Troubleshooting

### Error: `前向き台帳がありません`

- **Cause**: mcp-tradingview が未クローン、または台帳がまだ作られていない。
- **Solution**: 台帳の同期（`ledger-sync.yaml`）が動いているか確かめる。
  **台帳なしで振り返りを続けない**——技法との照合がすべて「確かめられない」になる。

### Error: `MOOMOO_ACC_ID を指定してください`

- **Cause**: 口座 ID が未指定。
- **Solution**: エラーが一覧の取り方を出す。**現物（CASH）の口座**を選ぶ。
  信用・デリバティブの口座には現物の約定が入っていない。

### Error: `1回の照会における時間範囲は360日を超えることはできません`

- **Cause**: 期間が長すぎる。
- **Solution**: script が 180 日ずつに割っているので、本来は出ない。
  出たなら開始日が極端に古い。**期間を区切って複数回に分ける。**

### Error: `日本株の決済がありません`

- **Cause**: 台帳は日本株だけを記録しているため、米国株の売買は照合できない。
- **Solution**: **異常ではない。** 米国株しか売買していない期間なら、そう報告する。

### 症状: 「建値が分からず除外」が多い

- **Cause**: 取得の開始より前に建てた持ち高。
- **Solution**: 開始日をさらに遡って取り直す。**残る限り、その取引は報告に入らない。**

### 症状: 照合できた取引が極端に少ない

- **Cause**: 台帳の期間（数か月）より前の売買が多い。
- **Solution**: **そのまま報告する。** 期間外を「技法が出ていなかった」と数えてはいけない。
