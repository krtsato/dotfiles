## 目的

ユーザーが Claude / Codex に繰り返し与えている指示は、グローバル指示ファイルに載せるべきルールの候補である。
訂正・手戻りのシグナルは、エージェントが外した期待の証拠である。
このスキルはログからその両方を抽出し、グローバル指示ファイルの更新案として提示する。

## 用語

本文では次の 4 語に統一する。表記ゆれ（「rollout」「トランスクリプト」「両ファイル」「更新対象」「追記案」「利用者」）はしない。

| 語 | 指すもの |
| --- | --- |
| セッション全文 | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` と `~/.claude/projects/<プロジェクト>/<session-id>.jsonl` の総称。1 セッションの発話・ツール呼び出しをすべて含む大きいファイル |
| グローバル指示ファイル | `~/.claude/CLAUDE.md`（Claude 用）と `~/.codex/AGENTS.md`（Codex 用）の 2 ファイルの総称。実体は dotfiles リポジトリ管理下にある |
| 更新案 | グローバル指示ファイルへ出す変更の提案。diff 形式で示す |
| ユーザー | 更新案を承認する人 |

## 前提条件

| 項目 | 内容 |
| --- | --- |
| 読み取り権限 | `~/.codex/history.jsonl`、`~/.codex/sessions/`、`~/.claude/history.jsonl`、`~/.claude/projects/` |
| 書き込み権限 | `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`（実体は dotfiles リポジトリのクローン内）、`~/.claude/skills/harvest-lessons/.last-run` |
| 実行環境 | Node.js（`npx markdownlint-cli2` 用）、git |
| リポジトリ | dotfiles リポジトリがローカルにクローンされていること（`git -C ~/dev/me/dotfiles` が通ること） |

## 想定ユースケース

| きっかけ | 実施すること | 得られるもの |
| --- | --- | --- |
| 「ログから教訓を抽出して」と依頼された | 前回実行時刻以降のプロンプト履歴を抽出し、繰り返し指示と訂正・手戻りシグナルを分類する | グローバル指示ファイルへの更新案（diff 形式） |
| 月次メンテナンスの節目 | 直近 1 か月分のログを対象に同じ手順を実行する | 記載済みなのに守れていない項目の一覧と、新規追記候補 |
| 同じ訂正を繰り返し受けている自覚がある | 訂正・手戻りシグナルのキーワードで該当プロンプトを抽出し、原因をセッション全文で特定する | 再発防止のための具体的な追記文面 |

## 対象ログ（保存場所）

| ソース | パス |
| --- | --- |
| Codex プロンプト履歴 | `~/.codex/history.jsonl` |
| Codex のセッション全文 | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` |
| Claude Code プロンプト履歴 | `~/.claude/history.jsonl` |
| Claude Code のセッション全文 | `~/.claude/projects/<プロジェクト>/<session-id>.jsonl` |

各ファイルのスキーマと抽出コマンドの例は [references/log-formats.md](references/log-formats.md) を参照。

## グローバル指示ファイル — 更新先

- `~/.claude/CLAUDE.md`（Claude 用のグローバル指示ファイル。実体は dotfiles 管理）
- `~/.codex/AGENTS.md`（Codex 用のグローバル指示ファイル。実体は dotfiles 管理）

## 手順

1. **前回実行時刻の確認**: `~/.claude/skills/harvest-lessons/.last-run` を読む（unix 秒 1 行）。
   無ければ直近 30 日分を対象とする。
2. **差分ログの抽出**: `~/.codex/history.jsonl` と `~/.claude/history.jsonl` から、
   前回実行以降（`ts` / タイムスタンプで比較）のユーザープロンプトを抽出する。
   件数が 300 件を超える場合はサブエージェント（Explore）に分析を委任し、
   メインコンテキストを汚さない。
3. **パターン抽出**: 抽出したプロンプトを、繰り返し指示と訂正・手戻りシグナルの 2 軸で分類する。
   分類の語彙と判定手順は [references/pattern-taxonomy.md](references/pattern-taxonomy.md) を参照。
   既にグローバル指示ファイルに記載済みの内容が繰り返されている場合は「記載済みなのに
   繰り返されている（エージェントが守れていない）」として別枠で報告する。
4. **更新案の提示**: 発見ごとに、(a) 証拠となるプロンプト引用、(b) 追記先ファイルとセクション、
   (c) 追記文面、を diff 形式で提示する。既存記述と重複・矛盾する案は出さない。
   グローバルに載せるべきでないプロジェクト固有の教訓は、該当プロジェクトの
   `tasks/lessons.md` への追記を提案する。
5. **承認と反映**: ユーザーの承認を得てから両方のグローバル指示ファイルへ反映し、
   `npx markdownlint-cli2 --config ~/dev/me/dotfiles/.markdownlint.yaml <file>` で lint する。
6. **実行時刻の記録**: 現在時刻（unix 秒）を `.last-run` に上書き保存する。

使用例（入力と出力のペア）は [references/examples.md](references/examples.md) を参照。

- [ ] `~/.codex/history.jsonl` から前回実行以降のプロンプトを抽出し、件数を記録した
- [ ] `~/.claude/history.jsonl` から前回実行以降のプロンプトを抽出し、件数を記録した
- [ ] 抽出件数が 300 件を超える場合はサブエージェントへ分析を委任した

- [ ] 記載済みなのに繰り返されている項目を別枠に分けた
- [ ] 発見ごとに証拠引用・追記先・追記文面を diff 形式で提示した

- [ ] `.last-run` を現在時刻で上書きした

## 完了基準

- markdownlint の警告が 0 件であること
- 提示した更新案がすべて「承認済み」か「保留（理由を明記）」のいずれかに区分されていること
- `.last-run` の値が、今回の実行開始時刻以上に更新されていること
- `~/.claude/CLAUDE.md` と `~/.codex/AGENTS.md` に共通化すべきルールを追記した場合、両ファイルの該当箇所が同一の文面になっていること

## 成功基準

| 種別 | 基準 |
| --- | --- |
| 定量 | 提示した更新案の diff がすべて承認済みか保留理由付きで決着している（未決着のまま報告を終えない） |
| 定性 | ユーザーが更新案の妥当性を diff だけで判断でき、元のログを読み返す必要がない |
| 定性 | 同じ訂正・手戻りシグナルが翌回の抽出で再び候補に上がらない（前回の追記が実際に効いている） |

## Troubleshooting

| Error | Cause | Solution |
| --- | --- | --- |
| 抽出結果が 0 件と出るが、実際にはログが存在する | ログファイルの読み取り権限が無い、またはパスの前提が崩れている（`~/.codex` / `~/.claude` の配置変更など） | 「0 件」と「確かめられなかった」を区別し、権限とパスの実在を確認してから報告する（無いと読めなかったを混同しない） |
| markdownlint で警告が出る | 半角英数字の前後スペース漏れ、見出しの `（）` 使用、行長超過など | 警告を回避せず、該当箇所を直して再実行する。無視して先に進まない |
| 抽出したプロンプトの一部が破損した JSON 行だった | ログローテーションや書き込み中の中断で行が途中で切れている | 壊れた行はスキップしつつ件数を数えて報告する（黙って無視しない） |

## 注意

- 2 つのグローバル指示ファイルで共通化すべきルール（言語・Git 規約・省略語彙など）は、
  両方に**同じ文面**で反映し、乖離させない
