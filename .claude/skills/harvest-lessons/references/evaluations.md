# 評価シナリオ

`harvest-lessons` が起動すべき場面と、起動すべきでない場面の一覧。Functional test の観点も併記する。

## Should trigger

| # | 入力の例 | 期待動作 |
| --- | --- | --- |
| 1 | 「ログから教訓を抽出して」 | 前回実行時刻を読み、Codex / Claude Code 双方の履歴を前回実行以降の範囲で抽出し、繰り返し指示と訂正・手戻りシグナルを分類して更新案を提示する |
| 2 | 「エージェント指示をログから改善して」 | 上記と同じ流れで実行し、グローバル指示ファイル（`~/.claude/CLAUDE.md` / `~/.codex/AGENTS.md`）への追記案を diff 形式で示す |
| 3 | 「月次メンテナンスで harvest lessons をやって」 | 定期実行の文脈でも同じ手順（前回実行時刻の確認 → 抽出 → 分類 → 提示 → 承認 → 反映 → 時刻更新）を踏む |

## Should NOT trigger

| # | 入力の例 | 期待動作 |
| --- | --- | --- |
| 1 | 「このプロジェクトの tasks/lessons.md に今日の学びを書いて」 | 起動しない。プロジェクト単位の追記はこのスキルの対象外（frontmatter の Do NOT use for に明記済み） |
| 2 | 「CLAUDE.md の品質を採点して」 | 起動しない。品質採点は eval 系スキルの役割であり、このスキルはログからの追記案作成が役割 |
| 3 | 「今日の Claude Code の履歴を見せて」 | 起動しない。ログの単純閲覧はこのスキルの対象外。閲覧だけなら `cat` / `jq` を直接使う |

## Functional tests

| カテゴリ | 確認内容 |
| --- | --- |
| 正しい出力（valid outputs） | 更新案が (a) 証拠プロンプトの引用、(b) 追記先ファイルとセクション、(c) 追記文面の 3 点を diff 形式で含んでいるか |
| 正常系（前回実行時刻が存在する） | `.last-run` の値以降のログだけが抽出対象になり、それより前のプロンプトが候補に混ざらないか |
| 失敗時（ログが読めない・空） | ログファイルが存在しない場合と、存在するが読み取り権限がない場合を区別して報告し、どちらも黙って 0 件と扱わないか |
| 境界（該当ログが 300 件を超える） | 300 件を超えた場合にサブエージェントへ分析を委任し、メインの会話へ生ログを流し込んでいないか |
