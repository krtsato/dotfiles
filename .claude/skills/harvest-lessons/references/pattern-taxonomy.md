# 繰り返し指示・訂正・手戻りシグナルの分類語彙

`harvest-lessons` の手順 3（パターン抽出）で使う分類語彙と判定例。
プロンプトを次の 2 軸のどちらか、または両方に分類する。

## 軸 1: 繰り返し指示

同種の指示が 3 回以上出現したものを候補とする。既にグローバル指示ファイルに記載済みの内容が繰り返し出ている場合は、
「記載済みなのに繰り返されている（エージェントが守れていない）」として別枠で報告する。

| 分類 | 該当するプロンプトの例 | 追記候補になりやすい先 |
| --- | --- | --- |
| commit 形式 | 「commit メッセージのフォーマットを直して」「Conventional Commits で」 | `rules/git.md` 相当のセクション |
| cleanup | 「local cleanup して」「マージ済みブランチを消して」 | 短い指示の読み方の表 |
| 進捗確認の抑止 | 「進んでるか止まってるか聞かないで」「節目ごとに報告して」 | 長時間の作業の運用ルール |
| 言語指定 | 「日本語で」「コメントは英語で」 | 伝え方のセクション |
| 検証の要求 | 「できてますか」「動作確認して」 | 原則（完了前に必ず検証する）相当 |
| スコープの絞り込み | 「そこだけ直して」「他は触らないで」 | 着手前のスコープ確認 |

分類の判定手順:

1. プロンプト本文から意図（何を求めているか）を要約する。
2. 上記の分類のいずれかに一致するか、または新規の分類が必要かを判断する。
3. 同一分類が 3 回以上あれば候補として残し、件数と代表的な引用を記録する。
4. 候補の内容を既存のグローバル指示ファイルで検索し、記載済みか未記載かを判定する。

## 軸 2: 訂正・手戻りシグナル

次のような表現を含むプロンプトを訂正・手戻りシグナルの候補とする。

| キーワード・表現 | 意味の目安 | 追加で確認すること |
| --- | --- | --- |
| 「戻して」「元に戻して」 | 直前の変更が期待と違った | 何を戻したか、原因になった変更を特定する |
| 「違う」「そうじゃない」 | 直前の実行結果が意図と異なる | 意図の取り違えの原因（指示の曖昧さかエージェント側の誤読か） |
| 「やり直し」「もう一度」 | 結果が使えず再実行が必要だった | 同じ失敗が繰り返されていないか |
| 「また失敗」「また同じ」 | 既知の失敗パターンの再発 | 過去の同種指摘が記載済みかを確認する |
| 「〜ではなく〜」 | 選んだ手段や表現が期待と違った | 訂正後の表現を追記候補の文面に反映する |
| 「本当に〜?」「わかった?」 | 実行結果への不信・確認要求 | 直前の報告が根拠を示せていたかを確認する |

判定手順:

1. キーワードに一致するプロンプトを抽出する。
2. 一致だけで訂正と断定せず、前後のプロンプトを読み、実際に手戻りが発生したかを確認する（キーワードが雑談や引用の中に含まれる場合は除外する）。
3. 原因の特定に文脈が要る場合は、該当セッションのセッション全文を個別に開く。
   **全文は読み込まず** `jq` や `grep` で該当箇所だけを抜き出す。
4. 原因がエージェント側の既知の弱点であれば、再発防止のための追記文面を作る。
