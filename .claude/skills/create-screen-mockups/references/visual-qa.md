# 見た目の点検表

一覧画像（4 画面ずつ並べた PNG）を読んで点検するときに読む。上から順に見て、1 件でも当てはまれば直して書き出し直す。共通の枠に触れたら全画面、触れていなければ該当画面だけでよい。

## 1. 壊れ（まず全画面で確認）

| 見え方 | よくある原因 | 直し方 |
| --- | --- | --- |
| ナビゲーションバー・下部バーが消えている | ビューア用の `nav` を隠す指定が `.navbar` にも当たる | ビューアの指定を `.viewer > nav` に限定する |
| 入力欄の仮の文字（プレースホルダー）や検索バーの文字が消える・縦に潰れる | 写真用のクラス `.ph`（正方形・背景付き）と名前が衝突 | 文字用のクラス名を別にする（`.hint`、`.placeholder`） |
| FAB やボタンの文字が縦書きになる | 絶対配置の親の幅が 0 で折り返す | `white-space: nowrap` |
| 1 文字だけ次の行に落ちる（「ダッシュボー/ド」「日/数」） | 幅に対して文言が長い | 文言を短くする。ナビゲーションバーのラベルは 4 文字以内（390px 幅に 5 項目並べると 1 項目約 78px で、5 文字目が次の行へ落ちる） |
| アイコンが英単語のまま表示される | フォントの部分集合に、そのアイコンが入っていない | フォントを取り直す |
| 一部の文字だけ別の書体に見える | 書体の部分集合に、その文字が入っていない | フォントを取り直す |
| 2 列の入力欄が上下にずれる | 入力欄同士の上余白の指定が、2 列の中にも効いている | 2 列の中では上余白を 0 にする |
| 白い背景の上で白いアイコンが見えない（カメラ） | 写真の明るい部分と重なる | 半透明の黒い円を敷く |

## 2. 注意の誘導

- 画面を 1 秒見て最初に目に入るものが、その画面の目的と一致しているか（例: ホームなら今日の予定。通知の帯ではない）。
- 見出し（700）と本文（400）の太さの差が見えるか。同じ太さに見えたら、システム書体の 500 指定が原因のことが多い。
- セクション見出しが本文より目立っていないか。目を引くべきは項目そのもの。
- 数字（金額・件数）が文章より大きく、通貨記号と単位が小さいか。
- 強調色が Primary 1 色に収まっているか。警告色は通知・遅延だけか。

## 3. 文字

- かなの字間が間延びしていないか（`palt` が効く書体か、かなが小さい書体でないか）。
- 12px 未満の文字がないか（12px は文字の階層の最小、Label）。住所・連絡先・遅延理由など現場で読む情報が 13px 以上か（Caption の大きい方。屋外や移動中でも読める下限）。
- 検索結果などで、語の一部だけが太字になっていないか。

## 4. 要件との整合

- 要件の表示項目が欠けていないか（例: 連絡先を「電話アイコンだけ」にしていないか）。
- 要件にない項目・状態・集計値・割合を足していないか。
- 未決の動き（自動保存、閉じても送信が続く、など）を画面の文言で約束していないか。
- 画面内に要件番号・内部の画面 ID が出ていないか。
- 件数の表示と、描いている行数が矛盾していないか（「7 件」と書いて 3 件だけ描く、など）。

## 5. 操作

- 主要操作が親指の届く位置（FAB、下部バーの右端）か。頻用の確定が右上だけにないか。
- 選択肢のシートが「現在の値」を示しているか。ラジオと状態アイコンが二重に並んでいないか。
- 失敗・中断・破棄の状態が、主要な作業（撮影・登録・署名など）について描かれているか。
- 意味のある図形（グラフの棒、進捗）が背景に溶けていないか（3:1 以上）。

## 6. 一貫性

- 同じ操作が同じ位置・文言・強調で出ているか。
- 同じ情報（場所の名前、状態）が画面ごとに違う書き方になっていないか。
- 同じ見出しの下に同じ項目名が重なっていないか（「場所」の見出しの下に「場所」の項目）。
