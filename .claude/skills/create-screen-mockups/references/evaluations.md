# 評価シナリオ

スキルを直したとき、または起動条件・出力の品質を確かめたいときに読む。各ケースは prompt と期待する結果、PASS/FAIL を機械的に判定できる assertion を持つ。

## 起動条件

| # | prompt | 期待 |
| --- | --- | --- |
| T1 | 「要件定義書から docs/requirements/screens に画面デザインのモックアップ画像を生成して。あとで直せるよう HTML/CSS も残して」 | 起動する |
| T2 | 「screens が AI くさい。洗練された見た目に作り直して、DESIGN.md も直して」 | 起動する |
| T3 | 「画面例を codex にレビューさせて、指摘を反映して書き出し直して」 | 起動する |
| T4 | 「Flutter の案件一覧画面の実装でレイアウトが崩れるので直して」 | 起動しない（実装コードの修正） |
| T5 | 「提案書から要件定義書を作って」 | 起動しない（要件定義は別スキル） |
| T6 | 「営業資料のスライドを作って」 | 起動しない（スライドは別スキル） |
| T7 | 「ロゴ画像を 1 枚作って」 | 起動しない（単発の画像生成） |
| T8 | 「画面例に提案書にない過剰な UI がないか点検して」 | 起動する（範囲の点検だけを行う） |

## 出力品質

### Q1: 要件書から一式を新規作成する

入力は、スキルに同梱した評価用の架空の要求資料（提案書）、要件書、確認事項（`evals/fixtures/`。現場点検アプリ、要件番号 001〜006、ブランド色 `#2E7D6B`）。提案書は「一覧の並び替え、地図・電話との連携、集計」を対象外と明記しており、範囲の点検の判定に使う。外部サイトに依存せず、誰が実行しても同じ条件で比べられる。

- **prompt**: 「同梱の評価用要件書の要件番号 001〜006 について、スマートフォンの画面例を docs/requirements/screens に作って。ブランド色は #2E7D6B」
- **期待**: DESIGN.md、画面例の原本、PNG、README がそろい、色の由来と未決の点が説明されている。
- **assertions**:
  - [ ] `verify-screens.sh` の終了コードが 0（登録表＝PNG＝README、要件 001〜006 がすべて対応、画面に要件番号なし）
  - [ ] 書き出しの失敗が 0 件（描画の例外・フォントの読み込み失敗がない）
  - [ ] 写真の登録に失敗の画面があり、確認事項の番号 2 が README の未決の点にある
  - [ ] PNG がすべて 780×1688（基準画面 390×844 の 2 倍。`sips -g pixelWidth -g pixelHeight` で確認）
  - [ ] コントラストの計算で、Primary と On Primary、On Surface と Surface、On Surface Variant と Surface がすべて 4.5:1 以上
  - [ ] DESIGN.md のフロントマターに `seed:` と、色一式の生成の出力と同じ `primary:` がある
  - [ ] DESIGN.md に「AI っぽく見せないための規則」の節がある
  - [ ] `app.js` の `Button` の `variant` は `primary` / `default` / `borderless` だけ。`ChoicePicker` の `displayStyle` は `chips` / `checkbox` だけ
  - [ ] README の「未決の点」に、確認事項の番号付きの行が 1 行以上ある
  - [ ] 範囲の点検で、全画面の要素が要求資料・要件書に対応づき、過剰な要素が 0（評価用要件書に無い発信・地図・並び替え・期間の切り替え・税の表示が画面に無い）
  - [ ] markdownlint の警告が 0

### Q2: 既存の画面例の見た目を作り直す

- **prompt**: 「screens が AI くさい。公式の UI 枠組みに沿って全部作り直して」
- **期待**: 既存 PNG を消して作り直し、全画面を点検表で点検し、崩れを直してから報告する。
- **assertions**:
  - [ ] 書き出し後に一覧画像を作り、全画面を読んだと報告に件数がある
  - [ ] 共通の枠（ナビゲーションバー・アプリバー・CSS）を変えた後の書き出しが全画面（一部の画面だけでない）
  - [ ] 枠線付きカードの多用・丸いバッジ・グラデーションがない（`styles.css` に `linear-gradient` が UI 用途で無い）

### Q3: codex のレビューを反映する

- **prompt**: 「codex にレビューさせて改善して」
- **期待**: 指摘を「直す・規則に書く・未決の点に書く・見送る」に仕分け、見送りに理由を付ける。
- **assertions**:
  - [ ] codex の出力本文が空でないことを確認してから仕分けている
  - [ ] 仕分けの件数の合計が codex の指摘件数と一致する
  - [ ] 直した画面の PNG が書き出し直されている（更新時刻が反映後）

## エッジケース

| # | 状況 | 期待する振る舞い |
| --- | --- | --- |
| E1 | 依頼者の企業サイトがない、または CSS を取れない | ロゴ画像の色、提案書の色、または依頼者に色を確認する。勝手に流行色を選ばない |
| E2 | ブランド色そのものに白文字を載せると 4.5:1 未満 | ブランド色は種として使い、文字とボタンには生成された Primary を使う。ブランド色はロゴだけ |
| E3 | Google Chrome がない | `CHROME` 環境変数で Chromium 系のパスを指定する。なければ依頼者に導入を依頼して止まる |
| E4 | codex CLI がない、または応答が空 | 点検表での自己点検に切り替え、codex のレビューは未実施と報告する |
| E5 | 要件の表示項目が未決（確認事項が未回答） | 仮の形で描き、README の未決の点に確認事項の番号付きで書く。画面上で確定したように見せない |
| E6 | 画面数が多い（40 を超える。一覧画像が 11 枚以上になり、codex の 1 回の入力に収まらない） | 一覧画像を分けて読み、codex にも分割して渡す。書き出しは全画面を 1 回で行う |
| E7 | 新しい文言を足したのにフォントを取り直していない | 該当文字が代替書体で出る。点検で見つけて取り直す |
| E8 | 画面を「それらしく」見せたくなる（一覧に並び替え、連絡先に発信ボタンなど） | 要求資料に根拠が無ければ置かない。範囲の点検で見つけたら消し、消した要素を報告する |

## 回帰ケース

スクリプトやひな形を直したら、次がすべて期待どおりか確かめる。

| # | 操作 | 期待 |
| --- | --- | --- |
| R1 | ひな形の `src/index.html` をクエリなしで開く | 登録表の先頭の画面が出る（例外にならない） |
| R2 | 存在しない `?screen=xyz` で開く | 先頭の画面に戻る |
| R3 | 描画関数で例外を投げる画面を書き出す | `failed: ... (data-render="error")` が出て、その PNG が消え、終了コード 1 |
| R4 | `verify-screens.sh` に存在しないディレクトリ、または登録 0 件の原本を渡す | FAIL を表示して終了コード 1（無言の合格をしない） |
| R5 | 書体を `BIZ UDPGothic`、太さを `400;500;700` にしてフォントを取る | `got 2 of 3 weights` で止まり、既存の `vendor/` は残る |
| R6 | 書体を設定ファイルで変えた後、環境変数なしでフォントを取り直す | 変えた書体のまま（既定に戻らない） |
| R7 | コントラスト計算に `nocolon` を渡す | 使い方を表示して終了コード 1 |
| R8 | `rgb(100%, 0%, 0%)` を含む CSS から色を集める | `#FF0000` として数える |
| R9 | README の対応表に `FR-01`・`2.3.1`・`FR-03` を書き、`verify-screens.sh --ids` に同じ 3 件の一覧を渡す。(a) そのまま実行 (b) 一覧に `2.3.2` を足し、README には `2x3x2` だけを書く (c) (a) の状態で画面の文言に `FR-03` を入れる (d) (a) の状態でコメント（行頭の `//`、行の途中の `//`、`/* */`）にだけ `FR-03` を書く | (a) 終了コード 0 (b) `2.3.2` を未対応として終了コード 1（`.` を任意の 1 文字として扱わない） (c) 終了コード 1 (d) 終了コード 0 |

## ベースライン比較

同じ要件書で、スキルなしとありの結果を比べる。スキルの価値は次の差に出る。

| 観点 | スキルなしで起きやすいこと | スキルありの期待 |
| --- | --- | --- |
| 色 | 手で選んだ汎用の色、白文字のコントラスト不足 | 企業サイト由来の種から生成、比を計算で確認 |
| 部品 | 枠線付きカードと丸いバッジの多用 | A2UI のカタログと Material 3 のリスト |
| 書体 | システム書体の 500 で見出しと本文の差が消える | 1 書体で 700 / 400 の差、`palt` |
| 検証 | 一部の画面だけ書き出して古い PNG が残る | 登録表＝PNG＝README を機械で照合 |
| 要件 | 要件にない項目や、未決の動きの約束が混ざる | 点検表で要件との整合を確認、未決は README へ |
