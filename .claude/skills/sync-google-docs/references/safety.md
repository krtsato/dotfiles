# 書き込み安全策

## 操作の選択

| 状況 | 使用する操作 | 禁止する操作 |
| --- | --- | --- |
| ローカル確認 | `generate` | API 書き込み |
| 新しい Google Docs | `publish --new-document` | 既存 document ID の指定 |
| 既存文書への新規タブ追加 | `publish --files` と `--create-missing-tabs` | 既存タブの選択 |
| 既存本文の変更 | `apply-patches` | `publish`、全文置換 |
| 画像だけの更新 | `sync-images` | 本文の再生成 |
| PDF 提出物 | `export-pdf` | 元文書のタブ削除 |

## 限定更新

1. 承認済みの変更だけで manifest を作る。
2. 対象タブ、旧値、期待一致件数を固定する。
3. 置換対象が 0 件または複数件なら停止する。
4. 書き込み直前に document revision を取得する。
5. 取得後に revision が変わった場合は反映しない。
6. 反映後に対象値を読み戻して検証する。
7. コメントの引用箇所と表示位置が維持されたことを確認する。

ドライランは、削除、表構造変更、多数タブ、初めて使う操作、一意性が不明な置換で必須とする。単純な一意置換でも、`--apply` 内部の事前検証と反映後検証を省略してはならない。

## 認証情報

- OAuth client JSON と token は Git で管理しない。
- Docker image へ COPY しない。
- bind mount 上の token は所有者だけが読める権限で保存する。
- コマンド出力、PR、評価レポートへ token や原本文を出さない。document ID と URL は同期結果の確認に必要な場合だけ示す。
- 認証エラーを別アカウントや広い権限で迂回しない。必要な権限を確認して再認証する。

## 画像の一時公開

- Google Docs API へ挿入する画像は、挿入処理中だけ Drive 上でリンク閲覧可能にする。
- 既定では無効とし、ユーザーが了承した場合だけ `allowPublicTemporaryImages=true` を設定する。
- 成功・失敗を問わず一時画像を削除し、残存ファイルが検出された場合は次の書き込みを停止する。
- 文書反映後に一時画像の削除だけが失敗した場合、反映済み文書を rollback せず、文書 ID と残存画像 ID を報告する。

## 失敗時

- 4xx と権限不足は設定または共有権限を直してから再実行する。
- 一時的な API 障害は、更新状態を再取得してから再実行する。
- 部分反映の可能性がある場合、同じ更新を即時再送せず、反映済み箇所を検証する。
- 画像一時ファイルや PDF 一時コピーの削除失敗は、残存 ID を秘密情報を含まない形で報告する。
- コメント、書式、対象外タブを保護できない場合は完了扱いにしない。
