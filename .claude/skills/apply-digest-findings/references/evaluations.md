# apply-digest-findings 評価シナリオ

## Should trigger (positive)

### P1: 滞留 draft PR の一括処理

**入力**: 「digest の draft PR が 17 本溜まっている。監査指摘を反映して merge できる状態にして」

**期待動作**: 各 PR 本文から指摘を抽出 → 字幕接地で改稿 → 4 つのゲート → 同ブランチに push →
PR 本文を更新。再監査で完了判定しない。

**期待出力**: `PR 372: applied 6 listed finding(s)` 形式の 1 行 × 本数、および反映件数の集計。

### P2: merge 済み digest の回収

**入力**: 「過去に merge された digest に未反映の指摘が残っている。直して」

**期待動作**: merge 済み PR 本文から指摘を抽出 → 改稿 → **1 digest = 1 commit** で 1 本の PR に集約。

**期待出力**: 1 PR・N commit。PR 本文に「再監査していない・残指摘の件数は未知」の明記。

### P3: 監査サービス停止中の作業

**入力**: 「Codex が落ちている間に進められることはある？」

**期待動作**: このスキルを提案し、指摘が既に PR 本文にあることを根拠として示す。

**期待出力**: 対象本数と指摘件数の見積り、および「新しい指摘を出すことだけが止まる」という切り分け。

### P4: 単一 PR の仕上げ

**入力**: 「PR #381 の指摘を反映して」

**期待動作**: その 1 本だけを処理する。

**期待出力**: 反映した指摘件数と、変更箇所の差分。

## Should NOT trigger (negative)

### N1: digest の新規著述

**入力**: 「この字幕から digest を作って」

**理由**: 新規著述は `digest-author.yaml`（`scripts/author-digest.sh`）の役割。このスキルは
**既存の digest に既存の指摘を反映する**もので、白紙からは書かない。

### N2: 監査の実行そのもの

**入力**: 「この digest を codex で監査して」

**理由**: 監査を投げるだけならスキル不要。このスキルは監査結果の**反映**を扱う。

### N3: technique note の起案

**入力**: 「この digest から technique note を作って」

**理由**: 知識層の別工程（`note-author.yaml`）。中立シグナルの符号化を伴い、判断基準が異なる。

### N4: 他リポジトリの Markdown 修正

**入力**: 「mcp-note の記事のレビュー指摘を反映して」

**理由**: 字幕接地・`[m:ss]` 錨・`derive-check` という前提が存在しない。

### N5: 指摘が存在しない digest

**入力**: 「PR #379 を仕上げて」（本文に指摘表が無い）

**理由**: 消化すべき一覧が無い。何もせず「指摘なし」と報告して終了する（改稿を発明しない）。

## Functional test

### Valid outputs

- 出力 digest の 1 行目が `---`
- `> 動画:` / `> 出典:` 行が入力と一字一句同じ
- `content_type` / `published_at` が不変
- `要点` と原則系セクションの全 bullet が `[m:ss]` 錨を持つ

### External calls succeed

- `gh pr view --json body` が本文を返す（新旧どちらの表形式でも抽出できる）
- `claude -p` が時間内に応答する（上限 1800 秒）
- `go run ./cmd/knowledge-derive-check` が終了コード 0

### Error handling

- 改稿がゲートに落ちたら**修正前を維持**し、落ちた出力を保存する
- 1 回だけ再試行する（確率的失敗の回収）
- 元字幕が見つからなければ、その PR をスキップして次へ進む（バッチ全体を止めない）
- `claude` がタイムアウトしたら、その PR を未処理として記録する

### Edge cases

- **前置き付き出力**: 1 行目が `---` でない → 最初の `---` まで削って続行
- **錨の連続**: `[1:37][18:20]` → 書式検査で落ち、再試行
- **`published_at` の書き換え**: 内容検査は通るので自前比較で検出し、巻き戻す
- **中間ファイル名が `.md` でない**: 検査対象ゼロになり `no derived digests found`。
  最終ファイル名で staging する
- **指摘 0 件**: 何もせず終了（改稿を発明しない）
- **digest が main に無い**（改名・削除済み）: スキップして記録する
