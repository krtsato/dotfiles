# 境界と数値条件

## 文書チャーター

要件定義の開始時に、次を台帳へ残す。提出文書へ掲載する必要はない。

| 項目 | 内容 |
| --- | --- |
| 読者と意思決定者 | 誰が判断し、誰が承認するか |
| 目的と利用場面 | この文書で合意することと、利用する工程 |
| 業務課題と業務結果 | 解決する課題、利用者または役割、期待する業務結果 |
| 合意範囲 | 意思決定者と決める事項 |
| 対象と優先順位 | 対象、対象外、優先順位とその根拠 |
| 内部決定 | 実装、運用、設計で決める事項 |
| 根拠資料 | 出典、版、合意状態、決定権限、更新可否 |
| 編集正本 | 要件変更を最初に反映する成果物 |
| 派生成果物 | 提出・確認用の文書、画面例、データ定義 |

根拠資料と編集正本は別である。根拠資料は原則更新せず、要件の決定は編集正本へ反映する。資料が矛盾する場合は、出典、矛盾内容、確認先、未決状態を記録する。

## 用語

取り違えると誤った成果物になる区別だけを定義する。

| 区別 | 意味 |
| --- | --- |
| 変更 / 反映 / 更新 | 変更は要件や名称の中身を改めること。反映は合意した決定を編集正本と派生成果物へ書き込むこと。更新はファイルや外部文書を書き換える操作 |
| 検証 / 点検 | 検証は linter・検索・読み戻しなど道具で確かめること。点検は根拠と照らして人が確かめること |
| 要求識別子 / 要件番号 / ID / 内部参照 | 要求識別子は出典の要求の番号。要件番号は編集正本で各要件に付ける番号。ID は文書・コメント・データ項目の番号。内部参照は番号のない資料へ付ける位置情報 |
| 根拠資料 / 一次情報 / 参考資料 | 根拠資料は判断に使う資料の総称で、一次情報は当事者が発した要求・決定の記録。参考資料は合意の根拠にしない理解補助（PoC、参考実装、他案件の例） |
| 編集正本 / 派生成果物 / 台帳 | 編集正本は要件を最初に反映する文書。派生成果物は画面例やデータ定義など編集正本以外の成果物。台帳は根拠と要件の対応表・矛盾・未決事項をまとめた提出しない記録 |
| 提出物 / 提出文書 | 提出物は契約で納める成果物の総称。提出文書はそのうち意思決定者へ渡す要件の文書 |
| 未決事項 / 確認事項 | 未決事項はまだ合意していない点。確認事項は未決事項を関係者へ問う提出文書の項目 |
| 内部検討 / 内部決定 | 内部検討は合意前の仮説・提案・判断経緯。内部決定は実装・運用・設計の担当が決めてよい事項 |
| 外部文書 / コメント付き外部文書 | 外部文書は Google Docs など外部サービス上のレビュー対象。コメント付き外部文書はそのうちコメントが付いたもの |
| 設計詳細 | 実装・技術方式・内部構造など、業務結果を変えない詳細 |

## 分類

| 判断質問 | 分類 |
| --- | --- |
| 利用者または業務に必要な結果か | 業務要件 |
| 意思決定者が確認する期待結果か | 受入条件 |
| 実現方法を変えても結果が変わらないか | 設計 |
| 配置、色、部品、具体的な操作表現か | UI 仕様 |
| 対象環境、提出物、検収、変更管理か | 契約または運用条件 |
| 合意されていない仮説、提案、判断経緯か | 内部検討または確認事項 |

具体的な方式は、明示要求、外部連携との互換性、利用者が確認できる結果、合意済み受入条件、法令・契約・セキュリティ制約のいずれかで必要な場合だけ固定する。明示的に要求された UI 操作、形式、方式は設計詳細として削除・抽象化しない。変更する場合は提案と合意を分ける。肯定要求から禁止、排他、全件などの制約を推定して追加しない。

## 数値条件

数値、性能、品質、AI 精度を受入条件または目標にする場合は、閾値だけを記載しない。次を同時に記録する。

| 項目 | 記録する内容 |
| --- | --- |
| 対象と分母 | 数える範囲、除外、単位、集計方法 |
| 測定方法 | 手順、実行条件、使用版、丸め |
| 評価資料 | 調整用資料と分けた資料、代表性、入手元 |
| ばらつき | 繰り返し測定の回数と結果の幅 |
| 併用指標 | 片方を改善して他方を悪化させない指標 |
| 根拠と状態 | 根拠、業務結果または利用者の作業負荷、合意済みか未決か |

測り方のばらつきより小さい差を合否条件にしない。精度や性能を要件に含めるかは案件ごとに合意し、含めない場合も開発中の評価方法を勝手に受入条件へ変えない。
