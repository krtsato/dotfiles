# 自動の片付けの取りこぼしを片付ける

## Important

**続いている会話のものは絶対に消さない。** 会話の記録 (`projects/*/<session>.jsonl`) が残っている session の
`file-history/<session>/` は、その会話の巻き戻し点そのもの。古くても消すと巻き戻しが壊れる。
だから**ファイルの古さでは判断せず、session 単位で判断する。**

| 場所 | 扱い |
| --- | --- |
| 会話の記録が残っている session の `file-history`・`subagents`・`tool-results` | **触らない**。公式の仕様どおり、記録が期限切れになったとき自動で一緒に消える |
| 会話の記録がどこにも無い session のもの | **取り残し**。このスキルの対象 |
| `plans/` | 自動で消える。対象外 |
| `memory/`・`jobs/`・`daemon/`・`plugins/` | Claude Code が消さない。**このスキルも消さない** |
| 会話の記録そのもの | 自動で消える。**消さずに、期限切れが残っていれば警告だけ**出す |

**消すと履歴から戻せない。** これらの木は git リポジトリ内にあるが `.claude/.gitignore` が除外している。だから既定は一覧のみで、`--apply` はゴミ箱へ移すだけ。`--purge` を使うのは利用者が明示的に求めたときに限る。

## 前提

- macOS で `~/.claude` がある。別の場所を試すときは `CLAUDE_DIR` で差し替える
- 日数は**このスキルでは持たない**。期限切れの判断が要る箇所 (見張り) は
  `~/.claude/settings.json` の `cleanupPeriodDays` を読む。未設定なら Claude Code の既定の 30 日
- `jq` が使えると `cleanupPeriodDays` を読める。無ければ 30 日として扱い、一覧に注意を出す

## ユースケース

### Use Case 1: 取りこぼしの棚卸し

- **Trigger**: 「`~/.claude` が重い」「残骸を片付けて」と言われた
- **Steps**:
  1. 引数なしで実行し、取り残された session の件数と容量を確認する
  2. 見張りの欄に警告が無いことを確認する
  3. `--apply` でゴミ箱へ移す
- **Result**: 続いている会話に触れずに、取り残しだけがゴミ箱へ移る

### Use Case 2: 自動の片付けが効いているかの確認

- **Trigger**: 「自動の片付けが効いているか」「古い記録が残ってないか」と聞かれた
- **Steps**:
  1. 引数なしで実行する
  2. 「自動の片付けの見張り」の欄を読む
  3. 警告が出ていたら `/status` の確認を促す
- **Result**: 期限切れの会話の記録の件数と最古の日付で答えられる

### Use Case 3: 古い file-history が残っている理由の説明

- **Trigger**: 「30 日より古い退避が残っているのは何か」と聞かれた
- **Steps**:
  1. 引数なしで実行し、該当の件数を見る
  2. 該当に入らない古い退避は、続いている会話のものだと説明する
- **Result**: 仕様どおりに残っているものと、取り残しとを区別して答えられる

## 対象と判定

| 種類 | 場所 | 中身 |
| --- | --- | --- |
| `file-history` | `file-history/<session>/` | 編集前のファイルの退避 (巻き戻し用) |
| `subagents` | `projects/<p>/<session>/subagents/` | subagent ごとの記録 |
| `tool-results` | `projects/<p>/<session>/tool-results/` | ツールが取得した `.json` / `.pdf` / 画像 |

**判定は 1 つだけ。** その session の会話の記録 `projects/*/<session>.jsonl` が、どの `projects` 配下にも無ければ取り残し。
この確認が途中で失敗したら (読めないフォルダがある)、全 session が取り残しに見えてしまうので、判定せずに非 0 で終わる。

## 使い方

```bash
~/.claude/skills/prune-agent-storage/scripts/prune-agent-storage.sh --apply
```

| 指定 | 動作 |
| --- | --- |
| なし | **一覧だけ出す。何も片付けない** |
| `--apply` | ゴミ箱へ移す。`~/.Trash/agent-prune-<日時>/` に**元の階層を保って**入る |
| `--purge` | 完全に消す。**取り消せない** |
| `--only KIND` | 1 種類だけに絞る。`subagents` / `tool-results` / `file-history` |

迷ったら `--apply` を選ぶ。ゴミ箱に入れておけば戻せるため、`--purge` は既定の選択肢にしない。

### 言葉の決まり

同じ操作を別の語で呼ばない。本文・スクリプトの出力・参照文書はすべてこの 3 語を使う。

| 語 | 指すもの | 戻せるか |
| --- | --- | --- |
| **移す** | `--apply`。ゴミ箱へ入れる | **戻せる** |
| **消す** | `--purge`。完全に取り除く | **戻せない** |
| **片付ける** | 上の 2 つをまとめて指すとき | — |

この 3 語はファイルに対する操作を指す。**空になったディレクトリだけは「取り除く」**と呼び分ける。
会話のデータを指す語も統一する。会話の記録 (`.jsonl`)、session (1 つの会話)、取り残し (記録が無い session のデータ)。

## 手順

**1. 一覧を出す。** 引数なしで実行する。取り残された session の件数、種類ごとの内訳、古い順の上位 10 件が出る。

**2. 見張りの欄を読む。** 期限切れの会話の記録が残っていれば、件数と最古の日付が警告として出る。警告があれば自動の片付けが止まっている可能性がある。**ここでは消さず**、利用者に `/status` の確認を促す。

**3. 取得物を確認する。** `tool-results` には調査の元資料が残っている場合がある。**片付ける前に中身を見る。** 必要なものがあれば別の場所へ退避してから進む。

**4. 片付ける範囲を確かめる。** 判断の難しいものが含まれていたら、`AskUserQuestion` で「全部」「1 種類だけ」「やらない」を選ばせる。**勝手に `--purge` を選ばない。**

**5. ゴミ箱へ移す。** `--apply` を付けて実行する。階層が保たれるので、戻すときに元の位置が分かる。

**6. 結果を照合する。** 出力の件数と、ゴミ箱に入ったファイル数が一致することを確かめる。そのうえで引数なしで再実行し、該当が 0 件になったことを確認する。

## 完了基準

次の 4 つがすべて満たされたときに完了とする。

- **該当が 0 件**になる。引数なしの再実行で確認する
- ゴミ箱に入ったファイル数が、出力の「片付けたファイル数」と**一致する**
- 続いている会話の `file-history`・`subagents`・`tool-results`、`memory`、`plugins`、会話の記録の件数が**実行前と変わらない**
- 利用者へ「移した件数」と、見張りの警告の有無を報告済み

## 落とし穴

**古い退避が残っていても取り残しとは限らない。** 30 日より古い `file-history` や `subagents` の大半は、会話がまだ続いているために仕様どおり残っている。件数が多く見えても、このスキルの該当にならなければ正常。

**会話の記録が消えた直後は、自動の片付けが一緒に消す。** 取り残しは、自動の片付けが取りこぼしたものに限られる。件数が少ないのが普通。

**自動の片付けが止まっていると、期限切れの記録が残る。** 設定ファイルが読めないなどで止まる。見張りの警告が出たら `/status` を確認する。このスキルで会話の記録を消して解決しない。

**取り残しは会話の記録の有無だけで決まる。** 会話の記録を手で消した session や、別の場所へ動かした session のデータも取り残しに入る。動かしたものがあれば、先に戻す。

**空になったディレクトリは取り除かれる。** 移動後、中身が無くなった階層は取り除く。続いている会話の階層と根は残す。

## Troubleshooting

エラーが出たら黙って飛ばさず、原因を突き止めてから進む。**件数を減らしたり対象を狭めたりして「通ったことにする」のは禁止。**

### Error: "claude directory not found: ..."

**Cause**: `CLAUDE_DIR` が誤っている、または `~/.claude` へのシンボリックリンクが切れている。

**Solution**:

1. リンクの指す先を `stat -f '%Y' ~/.claude` で確認する
2. 指す先が存在しない場合は dotfiles の配置をやり直す
3. 検証中であれば `CLAUDE_DIR` に渡したパスの綴りを確認する

### Error: "--only must be one of: subagents tool-results file-history"

**Cause**: 種類名の綴り違い。`plans` は対象から外れた。`tool-result` のような単数形も通らない。

**Solution**: 表記は表のとおり。複数種類を同時に絞ることはできないので、必要なら分けて実行する。

### Symptom: 「確かめられなかった箇所」が出て終了コードが 1 になる

**Cause**: 読めないフォルダがある。そこは「0 件」ではなく**未確認**。会話の記録の一覧を作る段階で出た場合は、取り残しの判定そのものを行わない。

**Solution**: 出た経路の権限を直して再実行する。無視して移さない。

### Symptom: 見張りに「cleanupPeriodDays を読めない」と出る

**Cause**: `settings.json` の値が整数でない、または `jq` が無い。30 日として扱われている。

**Solution**: `settings.json` の `cleanupPeriodDays` を 1 以上の整数に直す。`jq` は `brew install jq`。

### Symptom: 一覧は出るのに 1 件も移動しない

**Cause**: 一覧の出力をパイプで受けている。`set -eo pipefail` の下では、受け手が先に終了するとパイプが壊れ、移動処理に到達する前にスクリプトが終わる。

**Solution**: 出力をファイルへリダイレクトしてから読む。過去にこの原因で 605 件が 1 件も移動しなかった実例がある。詳細は `references/evaluations.md` を参照。

## 動きを変えたときの確かめ方

`CLAUDE_DIR` と `TRASH_DIR` を差し替えると、本物に触らずに検証できる。検証シナリオと functional test の一覧は `references/evaluations.md` にある。**次の 3 点は必ず含める。**

**1. 件数を 20 件より多くする。** 一覧は上位 10 件だけ表示する。過去に出力をパイプへ渡していたとき、**10 件を超えると処理全体が止まり、1 件も移動しないという不具合を出した。** 3 件のテストでは境界に届かず、本番の 605 件で初めて露呈した。

**2. 続いている会話を仕込む。** 会話の記録が最近のものと、そのファイルが 300 日前の `file-history`・`subagents` を置き、**残ることを確認する。** 古さで判断する実装に戻ると、ここで壊れる。

**3. 守るべきものを仕込む。** 300 日前の `memory/MEMORY.md`、`plugins/` 配下のファイル、`plans/` のファイルを置き、**いずれも残ることを確認する。**
