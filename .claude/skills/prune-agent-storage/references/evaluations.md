# prune-agent-storage の評価シナリオ

スキルが正しく起動し、正しく動くことを確かめるための一覧。起動判定のシナリオと、
スクリプトの動作を確かめる functional test に分かれる。

## 起動判定のシナリオ

### Should trigger

| # | 利用者の発話 | 期待する動き |
| --- | --- | --- |
| 1 | 「`~/.claude` が重いので容量を空けたい」 | 引数なしで一覧を出し、種類ごとの内訳を示す |
| 2 | 「古い plan を消して」 | `--only plans` で一覧を出し、各計画の見出しを見せる |
| 3 | 「session が溜まってないか見て」 | 一覧を出し、セッションログは自動で入れ替わる事実を添えて答える |
| 4 | 「半年前の計画を片付けて」 | `--only plans` を既定の 180 日で実行する |
| 5 | 「subagent の記録だけ消して」 | `--only subagents` で実行する |
| 6 | 「残骸をゴミ箱に移して」 | 一覧のあと `--apply` を実行する |

### Should NOT trigger

| # | 利用者の発話 | 理由 | 正しい振る舞い |
| --- | --- | --- | --- |
| 1 | 「memory を整理して」 | **永続が目的**のファイル。古さは不要を意味しない | このスキルを使わず、対象外である理由を説明する |
| 2 | 「セッションログを消して」 | 約 30 日で自動的に入れ替わる | 不要であることを実測値とともに伝える |
| 3 | 「plugins を消して」 | 導入したコード本体 | 対象外。削除したいならプラグイン管理の手順を案内する |
| 4 | 「`plans/design.md` を消して」 | **特定ファイルの名指し** | 日数で選ぶ仕組みは使わず、直接削除する |
| 5 | 「このリポジトリの `plans/` を整理して」 | プロジェクト配下は対象外 | `~/.claude/plans` との違いを確認する |
| 6 | 「ゴミ箱を空にして」 | 他のファイルまで消える | このスキルの範囲外。利用者自身に委ねる |

## Functional test

`CLAUDE_DIR` と `TRASH_DIR` を差し替えて実行する。本物の保存領域には触らない。

### 1. Valid outputs

| 確認項目 | 期待 |
| --- | --- |
| 2 段階のしきい値 | 200 日前の計画は該当、100 日前は**該当しない** |
| `--days 30` の上書き | 100 日前の計画も該当に**入る** |
| `--only plans` | 計画だけが該当し、他 3 種は 0 件 |
| 種類ごとの内訳 | 件数・容量・適用した日数が表示される |
| 計画の見出し | 一覧に `#` で始まる見出しの文字列が併記される |
| 移動先の階層 | `plans/` `projects/...` `file-history/...` が元の形で入る |

### 2. Edge cases

| 確認項目 | 期待 |
| --- | --- |
| **20 件を超える候補** | 一覧は 10 件で打ち切り、**全件が移動する** |
| 該当 0 件 | 何もせず「しきい値より古いファイルはありません」で終了 |
| 2 回続けて実行 | 2 回目は 0 件。**同じ操作を繰り返しても壊れない** |
| ちょうどしきい値の日数 | 「より古い」なので**含まれない** |
| `.md` 以外が `plans/` にある | 対象外。総数にも数えない |

### 3. Error handling

| 入力 | 期待する終了コード | 期待するメッセージ |
| --- | --- | --- |
| 存在しないディレクトリ | 1 | `claude directory not found: ...` |
| `--days abc` | 2 | `--days must be a non-negative integer` |
| `--days -5` | 2 | 同上 (負数も弾く) |
| `--only bogus` | 2 | `--only must be one of: ...` |
| 不明なオプション | 2 | `unknown option: ...` + 使い方 |
| 正常終了 | 0 | — |

### 4. 保護対象が残ること

**最も重要な確認。** 300 日前の日付を付けて仕込み、いずれも残ることを確かめる。

| 仕込むもの | 期待 |
| --- | --- |
| `projects/<proj>/memory/MEMORY.md` | **残る** |
| `plugins/<name>/index.js` | **残る** |
| `projects/<proj>/<uuid>.jsonl` | **残る** |
| `plans/` の 100 日前のファイル | **残る** (既定 180 日のため) |

## 過去に出した不具合

### 10 件を超えると 1 件も移動しなかった

**現象**: 一覧は正しく表示されるのに、移動が一切行われず終了する。

**原因**: 一覧の出力を `head -10` へパイプしていた。`set -eo pipefail` の下で受け手が
先に終了するとパイプが壊れ、`set -e` がスクリプト全体を終了させる。移動処理はその後ろに
あったため一度も到達しなかった。

**なぜ検出できなかったか**: 検証データを 3 件で作っていたため、10 件の境界に届かなかった。
**本番の 605 件で初めて露呈した。**

**対策**: `head` へのパイプをやめ、配列に読み込んでから 10 件で打ち切る。検証は必ず
**20 件以上**で行う。

## 成功基準

### 定量

- 起動判定のシナリオ 12 件のうち、**Should trigger 6 件すべてで起動**し、**Should NOT trigger 6 件すべてで起動しない**
- functional test の全項目が期待どおり
- 一覧から移動完了まで**ツール呼び出し 3 回以内**で終わる
- 保護対象の件数が実行前後で**変化 0**

### 定性

- 利用者が追加で指示を出さなくても、一覧を見せてから移動する流れになる
- 何が消え、何が残るかを利用者が読んで判断できる
- 同じ条件で何度実行しても同じ結果になる
- 削除を取り消したいときに、移動先から元の位置へ戻せる
