# prune-agent-storage の評価シナリオ

スキルが正しく起動し、正しく動くことを確かめるための一覧。起動判定のシナリオと、
スクリプトの動作を確かめる functional test に分かれる。

## 起動判定のシナリオ

### Should trigger

| # | 利用者の発話 | 期待する動き |
| --- | --- | --- |
| 1 | 「`~/.claude` が重いので容量を空けたい」 | 引数なしで一覧を出し、取り残しの内訳を示す |
| 2 | 「file-history が溜まってないか見て」 | 一覧を出し、続いている会話のものは対象外だと添えて答える |
| 3 | 「自動の片付けが効いているか確認して」 | 一覧の見張りの欄を読み、警告の有無を答える |
| 4 | 「取り残しだけゴミ箱に移して」 | 一覧のあと `--apply` を実行する |
| 5 | 「subagent の記録の残骸だけ消して」 | `--only subagents` で一覧を出し、明示的な要求なので確認のうえ実行する |
| 6 | 「30 日より古い退避が残っているのはなぜ」 | 一覧を出し、続いている会話のものだと説明する |

### Should NOT trigger

| # | 利用者の発話 | 理由 | 正しい振る舞い |
| --- | --- | --- | --- |
| 1 | 「memory を整理して」 | **永続が目的**のファイル。古さは不要を意味しない | このスキルを使わず、対象外である理由を説明する |
| 2 | 「会話の記録を消して」 | 自動で消える。続いている会話は消してはいけない | 不要であることを伝える。止まっていれば `/status` を案内する |
| 3 | 「plans を整理して」 | `plans/` は自動で消える | 対象外であることを説明する |
| 4 | 「plugins を消して」 | 導入したコード本体 | 対象外。取り除きたいならプラグイン管理の手順を案内する |
| 5 | 「あるプロジェクトの記録をまとめて消して」 | プロジェクト単位の操作 | `claude purge <作業フォルダ> --dry-run` を案内する |
| 6 | 「ゴミ箱を空にして」 | 他のファイルまで消える | このスキルの範囲外。利用者自身に委ねる |

## Functional test

`CLAUDE_DIR` と `TRASH_DIR` を差し替えて実行する。本物の保存領域には触らない。

### 1. Valid outputs

| 確認項目 | 期待 |
| --- | --- |
| 続いている会話 | 記録が最近の session の、300 日前の `file-history`・`subagents` は**該当しない** |
| 取り残し | 記録の無い session の `file-history`・`subagents`・`tool-results` は**該当する** |
| 種類ごとの内訳 | session 数・件数・容量が表示される |
| 見張り | 期限切れの会話の記録があると、件数と最古の日付を警告として出す |
| `cleanupPeriodDays` | `settings.json` に 10 を書くと、見張りの日数が 10 に変わり警告の有無が変わる |
| `--only file-history` | `file-history` の取り残しだけが該当し、他 2 種は 0 件 |
| 移動先の階層 | `file-history/...` `projects/...` が元の形で入る |

### 2. Edge cases

| 確認項目 | 期待 |
| --- | --- |
| **20 件を超える候補** | 一覧は 10 件で打ち切り、**全件が移動する** |
| 該当 0 件 | 何もせず「取り残されたファイルはありません」で終了 |
| 2 回続けて実行 | 2 回目は 0 件。**同じ操作を繰り返しても壊れない** |
| `settings.json` が無い | 30 日として扱い、警告は出さない |
| 取り残しの session の空ディレクトリ | 移動後に取り除かれる。続いている会話の階層は残る |

### 3. Error handling

| 入力 | 期待する終了コード | 期待するメッセージ |
| --- | --- | --- |
| 存在しないディレクトリ | 1 | `claude directory not found: ...` |
| `--only plans` | 2 | `--only must be one of: ...` |
| `--only bogus` | 2 | `--only must be one of: ...` |
| `--days 30` | 2 | `unknown option: ...` + 使い方 (日数の指定は廃止) |
| 読めないフォルダがある | 1 | `確かめられなかった箇所` |
| 正常終了 | 0 | — |

### 4. 保護対象が残ること

**最も重要な確認。** 300 日前の日付を付けて仕込み、いずれも残ることを確かめる。

| 仕込むもの | 期待 |
| --- | --- |
| 記録が最近の session の `file-history/<session>/` | **残る** |
| 記録が最近の session の `projects/<p>/<session>/subagents/` | **残る** |
| `projects/<p>/memory/MEMORY.md` | **残る** |
| `plugins/<name>/index.js` | **残る** |
| `plans/` のファイル | **残る** (自動で消える対象でこのスキルは触らない) |
| `projects/<p>/<session>.jsonl` | **残る** |

## 過去に出した不具合

### 10 件を超えると 1 件も移動しなかった

**現象**: 一覧は正しく表示されるのに、移動が一切行われず終了する。

**原因**: 一覧の出力を `head -10` へパイプしていた。`set -eo pipefail` の下で受け手が
先に終了するとパイプが壊れ、`set -e` がスクリプト全体を終了させる。移動処理はその後ろに
あったため一度も到達しなかった。

**なぜ検出できなかったか**: 検証データを 3 件で作っていたため、10 件の境界に届かなかった。
**本番の 605 件で初めて露呈した。**

**対策**: `head` へのパイプをやめ、配列に読み込んでから 10 件で打ち切る。検証は必ず
**20 件以上**で行う。

### ファイルの古さで判断して、続いている会話の退避まで消そうとした

**現象**: 30 日より古い `file-history`・`subagents` をすべて対象にしていた。実測で 593 件が、
会話の記録がまだ新しい「続いている会話」のものだった。消すと巻き戻しが壊れる。

**原因**: 「自動では片付かない」という前提で作っていた。実際は、会話の記録が期限切れになったとき
自動で一緒に消える仕様で、古いファイルが残るのは会話が続いているから。

**対策**: ファイルの古さをやめ、session の会話の記録が無いものだけを対象にした。

## 成功基準

### 定量

- 起動判定のシナリオ 12 件のうち、**Should trigger 6 件すべてで起動**し、**Should NOT trigger 6 件すべてで起動しない**
- functional test の全項目が期待どおり
- 一覧から移動完了まで**ツール呼び出し 3 回以内**で終わる
- 保護対象の件数が実行前後で**変化 0**

### 定性

- 利用者が追加で指示を出さなくても、一覧を見せてから移動する流れになる
- 何が消え、何が残るかを利用者が読んで判断できる
- 同じ条件で何度実行しても同じ結果になる
- 片付けを取り消したいときに、移動先から元の位置へ戻せる
